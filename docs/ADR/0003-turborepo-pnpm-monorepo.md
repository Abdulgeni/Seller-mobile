# ADR 0003: Turborepo + pnpm Workspaces with Hoisted Linker

- **Status**: Accepted
- **Date**: 2026-10-27
- **Decider**: Principal Mobile Engineer / Staff Architect

## Context & Problem Statement
A clean separation of concerns requires shared packages (`schemas`, `api`, `ui`, `config`) consumed by the Expo mobile app workspace. React Native's Metro bundler historically struggles with symlinked dependencies generated by standard pnpm isolate-mode trees.

## Decision
Use Turborepo with pnpm workspaces. Configure `.npmrc` with `node-linker=hoisted` to produce a hoisted flat `node_modules` structure compatible with Metro and React Native autolinking.

## Alternatives Considered
- **npm / yarn v1 workspaces**: Slower installs, prone to phantom dependency bugs.
- **Yarn Berry (PnP)**: Poor compatibility with React Native native builds and Metro autolinking.
- **Single monolithic app directory**: Leads to circular dependencies and blurred architecture boundaries between UI and domain schemas.

## Consequences
- **Positive**: Blazing fast turbo builds and cached task execution; clear module encapsulation; seamless Metro module resolution.
- **Negative**: Hoisted linker removes pnpm's strict phantom dependency isolation; requires strict ESLint and package.json discipline.
